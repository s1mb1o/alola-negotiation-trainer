More than a chatbot

The dialogue stays natural. The deal stays verifiable.

The language model writes dialogue. The negotiation engine selects legal actions, validates terms, and decides the outcome.

Source of truth

Structured state

The system stores offers, revisions, constraints, and events separately from prose. Free-form text cannot directly change the economic result.

Deal control

Deterministic validation

A complete package passes its term schema, hard constraints, and utility function. Acceptance refers to one exact offer revision.

Feedback

Evidence-linked review

Economics, process, and communication cards cite observed messages. The system distinguishes evidence from insufficient information.

Shared protocol

Humans and agents use one API

The Web UI, CLI, and an external agent use the same Player API. This supports training, replay, and comparable runs.

Method framework

Economics, process, and communication

ALOLA applies negotiation concepts as behavior and review rules. A methodology cannot replace actual deal terms or create hidden facts.

Harvard

Interests beyond positions, objective criteria, options, and mutually beneficial trades.

BATNA and ZOPA

The alternative and reservation utility stay in the authored model. The system does not infer an exact hidden ZOPA from dialogue.

Voss

Labels, mirrors, summaries, and calibrated questions appear only when they fit the current context.

Trust boundary

The model speaks. The engine decides.

ALOLA does not ask a language model to assign utility, validate hard constraints, or bind an agreement. These operations remain deterministic.

  • Hidden state stays hiddenA player receives only the projection allowed for that role.
  • A message is not an actionThe parser proposes an action. The engine validates and commits it.
  • History can be replayedRaw dialogue and structured events are stored at separate levels.
