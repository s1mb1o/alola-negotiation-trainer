# Окно обмена с LLM

Дата: 2026-09-25.
Решения: [DR-40](decisions/2026-09-24_llm-debug-window.md), [DR-41](decisions/2026-09-24_local-llm-debug-access.md), [DR-42](decisions/2026-09-24_llm-debug-links.md) и [DR-44](decisions/2026-09-25_complete-llm-requests.md).

## Запуск

1. Запустите API через `scripts/run-qwen-api.zsh` по инструкции в [COMMANDS.md](../COMMANDS.md).
2. Откройте <http://127.0.0.1:8172/llm-debug> в отдельном окне.
3. Журнал загрузится автоматически. Для локального окна ключ не нужен.
4. Продолжите игру на <http://127.0.0.1:8171/app/training>.

Локальный скрипт включает запись вызовов через `NEGOTIATION_LLM_TRACE=true`.
Для записи ключ администратора не требуется.
Запросы с loopback-адреса к loopback-адресу API получают доступ без ключа.
Если запрос содержит `Origin`, значение должно совпадать с адресом API.
Остальные запросы требуют ключ администратора.
Это правило действует только для журнала LLM.

## Удалённый административный доступ

При удалённом доступе страница показывает форму входа.
Введите ключ администратора. Не вводите ключ Qwen.
Скрипт использует заданный `NEGOTIATION_ADMIN_TOKEN`.
Если переменная отсутствует, скрипт создаёт случайный ключ в `.local/llm-debug-admin-token` с правами `0600`.
Каталог исключён из Git.

Чтобы скопировать созданный ключ на macOS, выполните команду из корня проекта:

```zsh
pbcopy < .local/llm-debug-admin-token
```

Вставьте ключ в форму доступа.
Страница хранит его только в памяти текущей вкладки.
Кнопка **Выйти** очищает ключ и показанные данные.
Перезагрузка страницы также удаляет ключ из памяти.
Страница не помещает ключ в URL или браузерное хранилище.

## Что видно

- Задача: ответ NPC, проверка ответа, социальная реакция, разбор результата или разбор предложения поставки.
- Сессия, провайдер, модель и время начала.
- Состояние вызова: ожидание, ответ получен или ошибка.
- Английские инструкции модели и переданные сообщения.
- Полный запрос каждой попытки: метод, адрес, заголовки, JSON и тайм-аут. Значения ключей доступа скрыты.
- Полученный текст ответа. JSON показан с отступами.
- Длительность, параметры генерации, расход токенов при наличии и число повторных транспортных попыток.
- Тип исключения и HTTP-статус при наличии. Текст исключения не записывается.

Системные инструкции используют простой технический английский по [DR-43](decisions/2026-09-24_ste-system-prompts.md).
Каждое предложение содержит одну мысль или инструкцию.
Ответы игроку используют язык сессии. Для MVP это русский язык.
Русские цитаты и точные фразы подтверждения сохраняются.
Старые записи показывают инструкции, которые были отправлены в момент вызова.
Новая версия промпта применяется к следующим вызовам после перезапуска API.

Список обновляется каждые две секунды после завершения предыдущего обновления.
Поле **Сессия** ограничивает список одним `session_id`.
Автоматическое обновление можно отключить.
Оформление следует светлой или тёмной теме системы.

## Прямые ссылки

Каждый вызов имеет адрес `/llm-debug#<trace_id>`.
При выборе вызова адресная строка обновляется.
Скопируйте адрес страницы или ссылку **Ссылка на вызов**.
Карточку вызова можно открыть в другой вкладке обычным действием браузера.

У каждого раздела также есть ссылка **Ссылка**:

- `/llm-debug#<trace_id>/instructions` — инструкции модели.
- `/llm-debug#<trace_id>/message-0` — первое входное сообщение. Индекс в адресе начинается с нуля.
- `/llm-debug#<trace_id>/response` — ответ модели.
- `/llm-debug#<trace_id>/parameters` — параметры и диагностика.
- `/llm-debug#<trace_id>/request-0` — полный исходящий запрос первой попытки. Повторные попытки имеют свои индексы.

Прямая ссылка, перезагрузка страницы и кнопки браузера **Назад** и **Вперёд** восстанавливают выбранную запись.
Фильтр сессии ограничивает список. Он не заменяет запись, явно выбранную по ссылке.
Автоматическое обновление сохраняет выбор.
Если запись отсутствует, страница показывает сообщение **Запись недоступна**.
Ссылка действует, пока запись есть в буфере процесса.
Перезапуск API или удаление старой записи из буфера делает ссылку недоступной.
Ссылка не содержит текст сообщения или ключи.

## История в запросе к модели

Каждый вызов получает контекст заново. Адаптер Qwen не продолжает серверную сессию модели.
Полная стенограмма хранится в базе. Сервис не отправляет её целиком в каждый вызов.

| Задача | Передаваемая история |
| --- | --- |
| Ответ NPC | Последние 12 сообщений, включая текущее сообщение игрока. Каждое сообщение ограничено первыми 1 000 символами после скрытия секретов. |
| Социальная реакция | Последние 6 предыдущих сообщений и отдельное `latest_message`. |
| Проверка ответа | Тот же контекст, что у генератора, и предложенный ответ для проверки. |

В скалярных сценариях генератор также получает `public_conversation_memory` размером до 8 000 символов.
Сервис строит её из публичных сообщений и событий всей сессии.
Она содержит текущую и отложенные темы, выбранные высказывания, вопросы и предложения.
Это ограниченная структурированная память. Она не сохраняет каждую раннюю реплику.
Генератор отдельно получает разрешённые условия, раскрытые причины и `training_context`.
В протоколе `supply-dialogue-v1` отдельная скалярная память не передаётся. Вместо неё передаётся разрешённый пакет условий и последние сообщения.

В журнале история может находиться внутри одного JSON-сообщения к модели.
Для ответа NPC ищите `untrusted_public_dialogue` и `public_conversation_memory`.
Для социальной реакции ищите `conversation` и `latest_message`.

## Границы

Запись начинается после запуска API с этой функцией.
Старые обращения к провайдеру не восстанавливаются из истории игры.
Журнал хранит до 200 вызовов текущего процесса с общим лимитом памяти.
Перезапуск API очищает журнал.
Вызовы benchmark-сессий не записываются.
Вызовы вне HTTP-запроса существующей учебной сессии не записываются.
Шаблонные реплики не вызывают LLM и не создают запись.

Одна запись соответствует вызову адаптера провайдера.
Внутренние HTTP-повторы не создают отдельные записи.
Журнал показывает полный JSON, который адаптер передаёт HTTP-клиенту.
Для Qwen этот JSON содержит `model`, `messages`, `max_tokens` и заданные параметры генерации.
Первое системное сообщение находится внутри `messages`.
Контекст, память и RAG-примеры видны там, где приложение включило их в сообщения.
Журнал также показывает текст ответа модели.
Он не показывает внутренние инструкции провайдера или заголовки, которые добавляет HTTP-библиотека.
Отсутствие секции полного запроса означает, что отправка ещё не зафиксирована.
Это возможно до отправки, при ошибке конфигурации или при использовании тестового провайдера без HTTP.
Состояние **Ответ получен** не означает, что игрок увидел этот ответ.
Проверка может вернуть `safe: false`. Тогда игрок получит запасную реплику.
Исход **Ошибка провайдера** также может привести к запасной реплике.

Журнал не сокращает инструкции, сообщения, JSON запроса или текст ответа.
Ограничения контекста приложения действуют до отправки и описаны выше.
Известные ключи и значения заголовков авторизации скрываются до записи в память.
Буфер хранит до 200 вызовов и до 64 МиБ сериализованных данных.
При заполнении буфера старые записи удаляются целиком.
Запись больше лимита также удаляется целиком.
Страница показывает недоступность удалённой записи по её старой ссылке.

Внутренние запросы могут содержать закрытые факты NPC и данные итогового разбора.
Локальные клиенты могут читать журнал без ключа. Удалённый доступ предназначен для администратора.
Обычный Player API и Session Inspector не получают эти данные.
Журнал не изменяет ответы модели, историю, условия сделки или оценки.

## Проверка

```sh
uv run pytest backend/tests/test_llm_trace.py backend/tests/test_openapi.py clients/tests/test_providers.py
node --check backend/app/static/llm-debug.js
node --test backend/tests/llm-debug-navigation.test.cjs
```

Проверки используют синтетические данные и провайдеры без сетевого доступа.
Они проверяют доступ, скрытие секретов, лимиты, состояние выполнения, ошибки, привязку к сессии и исключение benchmark-вызовов.
Для тестов навигации нужны установленные зависимости `frontend`, включая `jsdom`.
Тесты проверяют прямые ссылки, историю браузера, полные запросы, адреса разделов, удалённые записи и ответы, пришедшие после смены выбранного вызова.
